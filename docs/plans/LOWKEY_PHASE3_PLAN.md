# Lowkey phase 3: processing in the app, one model, start at login

Status: reviewed (2026-10-06), split into 3a/3b/3c after peer review. Builds on phase 2 (PR #47) and the native-app plan in issue #30.

## Where phase 2 left us
Lowkey owns the hotkey, capture, sounds and paste. After stop, it writes a WAV and runs `tmux-whisper inline process --json`. On the first real run:
- Stop → text took 2.3 s: 1.3 s transcription plus ~0.8–1.0 s of CLI overhead (bash boot, config load, WAV copy, ffprobe/ffmpeg padding, socket round-trips, history/bench/usage writes, JSON).
- Native paste took 50 ms, vs ~450 ms for the CLI's osascript.
- Microphone engine start was 45 ms cold (target < 20 ms).
- The Parakeet model is loaded by the separate `tmux-whisperd` daemon.

## Goals
1. **Stop → text ≈ transcription time.** Remove the CLI from the dictation path. Target: overhead < 50 ms beyond Parakeet's own time.
2. **Identical output.** Same cleanup, vocab, modes, paragraphs and British spelling as the CLI. Proven by tests, then by a shadow-compare period.
3. **One warm model.** When Lowkey runs, it serves the daemon socket, so the CLI, tmux flow, `transcribe` and agents use the app's in-process model. When Lowkey quits, the CLI falls back to starting `tmux-whisperd` as today.
4. **Always available.** Start at login; survive mic device changes.
5. **Keep history, bench and usage exactly as today.** Same files and formats, so `tmux-whisper usage`, `bench`, `history` and SwiftBar keep working.

Non-goals: LLM post-processing in Swift (Cerebras stays CLI-only, used as a fallback when enabled; it is off on this Mac), notarization/distribution, UI settings window, CLI rename.

## Design

### 1. Text pipeline in Swift (`LowkeyCore/TextPipeline`)
A port of the inline cleanup, in the CLI's order (process_inline_recording + bin/dictate-lib.sh):
1. `sanitizeArtifacts` (`[blank audio]` variants, spacing around punctuation): dictate_lib_sanitize_transcript_artifacts.
2. Fillers and repeats, only when `DICTATE_CLEAN`/config enables them, with repeat levels 0/1/2: dictate_lib_clean_fillers/repeats.
3. Mode resolution: `current-mode` file (auto or fixed), `modes/*/apps` matched against the target app, `flows`, and the default inline mode (mode.sh get_current_mode/detect_mode). The app passes the frontmost app's name, as today.
4. Vocab corrections: global `vocab` plus the mode's `vocab` (dictate_lib_apply_vocab_corrections, 115 lines; regex/word-boundary semantics must match exactly).
5. Mode cleanup: auto paragraphs for code (70 words) and long (55) modes (dictate_lib_auto_paragraphs).
6. British spelling (dictate_lib_normalize_british_spelling, word list).

Config comes from a richer `tmux-whisper app-config --json`: clean flags, repeat level, the British spelling toggle, the postprocess flag, model path/version, and modes/vocab directory paths. The app re-reads it on Reload Settings and when config files change (FSEvents on ~/.config/dictate).

**Parity, proven before switching:**
- **Differential corpus.** `tests/fixtures/cleanup/` holds ~150 crafted inputs (punctuation, artifacts, fillers, stutters, vocab hits at word boundaries/case/punctuation, every mode, long text for paragraphs, US→UK words). It also holds expected outputs generated by running the bash functions (`tests/gen-cleanup-fixtures.sh`, rerun when bash cleanup changes). Swift tests assert byte-equal output, and CI runs both sides so drift fails the build.
- **Shadow compare in real use.** `[app] verify_pipeline = true` (default on during rollout). After delivering the native result, the app runs `tmux-whisper inline process` in the background on the same WAV and logs any text mismatch, with both texts, to app.log. Delivery never waits on it. Turn it off once a few days of use show zero mismatches.

### 2. Transcription in the app
- `ASREngine` gains `transcribe(samples: [Float], modelURL:, version:)` using FluidAudio 0.12.6's `transcribe(_ samples: [Float], source: .microphone)`, through the existing SerialGate.
- Port the CLI's pre/post steps that affect accuracy:
  - **Tail padding** (`DICTATE_TRANSCRIBE_TAIL_PAD_MS`, default 500 ms of silence appended).
  - **1 s minimum padding.**
  - **Tail rescue**: for audio ≥ 12 s, re-transcribe the last 8 s and merge, using a Swift port of `merge_transcript_chunks`, the word-overlap merge in Python (differential-tested like the cleanup).
  - Silence trim is off by default; it stays CLI-only.
- The model loads and warms at app launch. One `ASREngine` serves both the app and the socket.
- If LLM post-processing is enabled, or anything native throws, fall back to phase 2's `inline process` path for that dictation (logged).

### 3. Recording history, bench and usage
These must stay byte-compatible with the CLI's files and locking:
- **Choice:** keep one writer. After delivery, the app runs a new `tmux-whisper inline record --json` in the background with the payload on stdin (raw/processed text, mode, app, timings, startup source). It reuses `save_history`, `append_bench_entry` and `usage_record_delivery`.
  - Off the critical path, so its ~100 ms doesn't matter.
  - It keeps the formats and the usage-ledger flock single-sourced.
- Bench rows get `app:native` as the startup source, so the two paths can be compared.
- Processing markers: the app writes the marker file the CLI and SwiftBar read while transcribing, so the "idle" checks and SwiftBar stay correct.

### 4. The app serves the daemon socket
- At launch, Lowkey takes over `~/.config/dictate/.cache/tmux-whisperd.sock`:
  1. Ping it. If a `tmux-whisperd` is serving, read `<socket>.meta` and send SIGTERM. The daemon releases the socket immediately and drains its accepted work (phase 1 behaviour).
  2. Bind with `UnixSocketServer`, sharing the app's `ASREngine`.
  3. Write `<socket>.meta` with `owner=lowkey`, `pid`, `version`.
- CLI changes:
  - `restart_stale_tmux_whisperd` and `tmux_whisperd_is_current` treat `owner=lowkey` as never stale and never signal it.
  - `ensure_swift_parakeet_daemon` keeps working unchanged: ping succeeds against the app.
  - `debug`/`status` show the socket owner.
- On quit, the app releases the socket and removes meta. The next CLI use starts `tmux-whisperd` as today.
- **Risk to verify:** two processes using the Neural Engine model briefly during takeover (the daemon draining). Fine memory-wise (~20 MB footprint), but measure latency.

### 5. Start at login and robustness
- `SMAppService.mainApp.register()` behind a menu toggle "Start at Login" (default on after first successful dictation). Verify it works for a self-signed app in ~/Applications on macOS 27.
- Microphone:
  - Decide from phase 2 data. If warm `engine.start` stays > 20 ms, add `[app] keep_mic_warm` (engine running between takes, accepting the menu-bar mic indicator).
  - On device change mid-take, keep the partial take (phase 2). Between takes, rebuild the engine for the new default device.
- Watch the CLI config for changes (FSEvents) instead of requiring Reload Settings.

## Build order: three stages, each measured before the next

**3a — Cleanup in Swift, proven identical (no behaviour change)**
- TextPipeline in LowkeyCore. Use NSRegularExpression (ICU) to stay close to Perl, and compare UTF-8 **bytes** in tests, not Swift `String ==` (which accepts canonical equivalence).
- Differential corpus generated from the bash functions. Cover:
  - Vocab is case-insensitive, with acronym compaction.
  - Quirks preserved as-is (e.g. `actuallyish` → `ish`).
  - Config combinations (clean on/off, repeat levels, British spelling on/off, fixed vs auto mode).
  - Unicode and line-ending cases; cascading vocab rules.
- Shadow-compare harness ready (used from 3b).

**3a status (2026-10-09): done, not yet wired into the app.**
- `LowkeyCore/Cleanup/`: `TextPipeline` (stage order of `process_inline_recording`, with bash's `$(...)` newline stripping between stages), `TextCleanup` (sanitize, fillers, repeats, paragraphs, British spelling), `VocabCorrector`, `ModeResolver`, `CleanupSettings` (the new `cleanup` section of `app-config --json`), `ShadowCompare` (for 3b's `verify_pipeline`).
- Perl semantics reproduced: per-line processing (`perl -p`); byte-mode filters run on a byte-faithful view (UTF-8 bytes ≥ 0x80 mapped to private-use scalars), so `\s`/`\b`/`/i` stay ASCII-only as in Perl; vocab uses Perl's Unicode `\s` list, code-point lengths/ordering and literal replacements; mode folders in C-locale byte order; app names matched as BSD grep BREs.
- Corpus: `tests/fixtures/cleanup/` (`cases.json` + seeded random cases → `expected.json`, 1,015 stage and 135 pipeline cases), generated from the real bash by `tests/gen-cleanup-fixtures.sh` (pipeline cases run the new `tmux-whisper inline cleanup --json` with `LC_ALL=C`, scratch HOME and config copies). CI (macOS Swift workflow) runs `--check` before `swift test`.
- Cost: ~4 ms per 200-word take (debug build), including config reads and vocab compilation.
- Locale: the native pipeline reproduces only the C locale (what Lowkey's CLI runs in today: no LANG/LC_* in its environment or ~/.zshenv). `app-config` reports the effective `locale_ctype`/`locale_collate`; any other value returns `.needsCLI`, so that dictation uses the CLI path.
- The extracted bash helpers set `CLEANUP_TEXT`/`RESOLVED_MODE` instead of printing, so a failing stage behaves exactly as before (aborts with its status under `set -e`, continues where errexit is off); covered by a flow-parity failure-injection test.
- Known, accepted differences (none reachable from Lowkey today):
  - No app name: the CLI asks System Events for the frontmost process; Swift uses the default inline mode. Lowkey always passes the frontmost app's name.
  - App names containing `[` (a grep bracket expression), a newline, or BRE `\{…\}`/`\(…\)`: Swift never matches/treats them literally.
  - Invalid UTF-8 in config files is decoded leniently; Unicode-version differences between Perl 5.34 and ICU only affect characters newer than Unicode 13.

**3b — Drop the CLI from the dictation path (model stays in tmux-whisperd)**
- Swift socket client (TmuxWhisperKit protocol) to the existing daemon:
  - Short ping timeout; a longer per-request timeout scaled to audio length.
  - One reconnect retry, and an `ensure` fallback via the CLI if the daemon is down.
- Port tail padding and tail rescue (last 8 s for audio ≥ 12 s, merge via a Swift port of `merge_transcript_chunks`, differential-tested). Silence trim stays CLI-only: dictations with it enabled use the CLI path.
- New: pad sub-second takes to FluidAudio's 1 s minimum (a behaviour improvement, tested separately).
- Audio parity: keep sending 16-bit PCM WAV (as phase 2) so Parakeet's input is unchanged.
- Native cleanup → delivery → **then** persistence:
  - `tmux-whisper inline record --json` on a serial background queue.
  - Fields: a unique take ID, timestamps captured at the event, and delivery status.
  - Usage is counted only after a successful paste (fixes the deferred phase 2 finding).
  - Add locking and unique filenames to history/bench writes.
  - Processing markers per take.
- `[app] verify_pipeline` shadow compare on for a few days.
  - Compare text with `inline cleanup --json` on the same raw transcript (side-effect free). A whole-take `inline process` shadow run would record usage, bench and history a second time; if whole-take verification is wanted, add a no-record option first.
  - Compare against the same settings snapshot the native run used; fall back when `cleanup` is absent (older CLI) or `requiresCLI`.
- Fallback to the phase 2 `inline process` path for LLM post-processing, silence trim, or any native error.

**3c — Model in the app and socket ownership (only after 3b is stable)**
- In-process ASREngine shared with a UnixSocketServer the app hosts.
- Takeover:
  - A startup/takeover lock.
  - Atomic meta publication only after a successful bind (`owner=lowkey`).
  - Short health checks.
  - Clients retry once on connect failure.
  - Graceful release on quit.
  - Stale socket/meta recovery after crash or force-quit.
- CLI respects `owner=lowkey` (never restarts or signals it).
- Stress tests: simultaneous app/CLI launch, takeover during a transcription, force-quit and relaunch, login-item launch with a CLI-started daemon already running. Measure overlapping model memory on 8 GB.
- Then: start at login (SMAppService), config watching, the keep-mic-warm decision from data.

Release v0.10.0 after 3b (biggest user-visible win at moderate risk); 3c ships in a later release.

## Measurements that gate "done"
- Per-stage timings logged per take: queue, preprocessing, ASR, cleanup, delivery (excluding the configured 90 ms activation / 35 ms send delays), persistence.\n- 3b: stop → delivered overhead beyond ASR and configured delays < 100 ms median over 20 dictations; 3c: < 50 ms.
- Zero shadow-compare mismatches over ≥ 2 days of use.
- Hotkey → capturing < 50 ms warm.
- CLI `transcribe` / tmux flow work while Lowkey runs, through the app's socket, and after it quits, via the daemon.
- Microphone and Accessibility grants persist across rebuilds and the login-item launch.
